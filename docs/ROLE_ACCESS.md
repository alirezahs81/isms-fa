# کنترل دسترسی مبتنی بر نقش (RBAC)

این پروژه دسترسی کارکنان را با عضویت در گروه‌های Django کنترل می‌کند. داشتن `is_staff=True` به‌تنهایی مجوز ورود به صفحات عملیاتی نیست. کاربران superuser همچنان دسترسی کامل دارند.

## راه‌اندازی

پس از اعمال کد:

```powershell
python manage.py migrate
python manage.py setup_isms_roles
```

سپس با حساب superuser وارد پنل مدیریت Django شوید و از بخش **Authentication and Authorization → Users**، هر کارمند را به گروه مناسب اضافه کنید. کاربر باید `is_staff=True` نیز داشته باشد.

## نقش‌ها

| گروه | دسترسی |
|---|---|
| `isms_admin` | عملیات کامل برنامه؛ مدیریت کاربران همچنان فقط برای superuser |
| `isms_finance` | داشبورد و گزارش‌ها، مشاهده مشتری و سرویس، فاکتور و پرداخت |
| `isms_support` | عملیات مشتری و سرویس؛ بدون دسترسی به صفحات مالی |
| `isms_viewer` | مشاهده فهرست پلن‌ها؛ بدون دسترسی به اطلاعات مشتری و مالی |

**مهم:** کارکنان فعلی که فقط `is_staff=True` دارند، تا زمان تخصیص گروه مناسب دسترسی برنامه را نخواهند داشت. ابتدا گروه‌ها را بسازید و کاربران را تخصیص دهید؛ این تغییر هیچ داده‌ی تجاری را حذف یا تبدیل نمی‌کند.

## اصول امنیتی

- درخواست‌های بدون نقش معتبر با پاسخ 403 رد می‌شوند.
- کاربر عادی حتی با عضویت اشتباه در گروه، بدون `is_staff` مجاز نیست.
- superuser برای عملیات اضطراری و مدیریت نقش‌ها حفظ شده است.
- رمزنگاری داده‌های حساس در مرحله‌ای جداگانه انجام می‌شود تا مهاجرت داده‌های فعلی بدون کلید رمزنگاری و برنامه بازیابی، در معرض خطر قرار نگیرد.
